# DD-004: Provider-Neutral Core Domain with CRM Anti-Corruption Layer

- **Decision ID:** DD-004
- **Status:** Accepted
- **Date:** 2026-08-08
- **Owner:** Domain Architecture Board

## Decision

The core domain remains provider-neutral. Microsoft Dynamics 365 and other external provider concepts are isolated behind anti-corruption layers in integration contexts.

## Context

The business architecture specifies that Microsoft Dynamics 365 is the first specialization, not the universal domain model. Provider-specific concepts must not contaminate the core domain.

## Alternatives

1. Model Dynamics 365 entities directly in the core domain
2. Keep core domain provider-neutral with adapter mappings
3. Create a separate bounded context per provider in the core

## Rationale

Provider neutrality preserves future extensibility to Salesforce, NetSuite, and other CRMs. The CRM Synchronization context owns the ACL and mappings.

## Impact

- Core domain objects use names like Company, Contact, Lead, Opportunity, Meeting.
- Dynamics IDs are stored in CRMRecordReference or SyncMapping, not core entities.
- Future CRM providers can be added without changing core domain logic.
