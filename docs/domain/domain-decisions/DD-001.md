# DD-001: Mission and AgentExecution as Separate Aggregates

- **Decision ID:** DD-001
- **Status:** Accepted
- **Date:** 2026-08-08
- **Owner:** Domain Architecture Board

## Decision

`Mission` and `AgentExecution` are modeled as separate aggregates. Mission owns mission lifecycle, objectives, and plan. AgentExecution owns the lifecycle and outcomes of individual agent task runs.

## Context

A common anti-pattern is to place all agent execution state inside the Mission aggregate, creating a giant aggregate that hinders concurrency, scalability, and independent evolution.

## Alternatives

1. Single giant Mission aggregate containing all executions
2. AgentExecution embedded as an entity inside Mission
3. Separate aggregates with event-based coordination

## Rationale

Mission coordination and agent execution have different consistency needs and lifecycles. Separating them allows independent scaling, failure isolation, and clearer ownership. Mission reacts to AgentExecution events.

## Impact

- Mission aggregate remains small and focused on business objective and plan.
- AgentExecution can be tracked, retried, and audited independently.
- Cross-aggregate consistency is eventual, driven by domain events.
