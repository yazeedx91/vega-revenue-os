# DD-002: Tenant as Explicit Aggregate Root

- **Decision ID:** DD-002
- **Status:** Accepted
- **Date:** 2026-08-08
- **Owner:** Domain Architecture Board

## Decision

`Tenant` is modeled as an explicit aggregate root. It owns tenant lifecycle, configuration, policies, and integration settings. Other tenant-scoped aggregates reference TenantId but remain independent.

## Context

Multi-tenancy is a first-class business and security boundary. Treating Tenant as merely a cross-cutting identifier would lose the ability to reason about tenant lifecycle and configuration in the domain.

## Alternatives

1. Tenant as only a cross-cutting value object
2. All tenant-owned entities inside a giant Tenant aggregate
3. Tenant as aggregate root with independent child aggregates

## Rationale

Option 3 balances explicit ownership with small aggregate boundaries. Tenant configures the system; other aggregates operate within the tenant boundary without being nested.

## Impact

- Clear ownership of tenant-level configuration and policies.
- No giant Tenant aggregate.
- TenantId is a required value object on every tenant-scoped aggregate.
