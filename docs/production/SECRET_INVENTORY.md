# ProjectX Production Secret Inventory

All values are names. Never store actual secret material in Git or in plaintext CI/CD variables.

## Secret Conventions

- Current/alias secrets hold the currently active key material.
- `*-key-version` secrets hold the active version string (e.g. `v1`).
- `*-keys/{version}` hold historical key material for durable artifact decryption.
- Newer keys are added without removing historical `*-keys/{version}` entries until all durable artifacts referencing the old version are re-encrypted or no longer needed.

## Recipient Protection Secrets

| Secret Name | Purpose | Rotation Notes |
|-------------|---------|----------------|
| `projectx/contact-channel/encryption-key-version` | Current encryption key version | Update when rotating current key |
| `projectx/contact-channel/encryption-key` | Alias/current encryption key (256-bit hex) | Keep as alias or fallback |
| `projectx/contact-channel/encryption-keys/{version}` | Historical encryption keys | Do not delete while artifacts reference them |
| `projectx/contact-channel/hmac-key-version` | Current HMAC key version | Update when rotating current key |
| `projectx/contact-channel/hmac-key` | Alias/current HMAC key (256-bit hex) | Keep as alias or fallback |
| `projectx/contact-channel/hmac-keys/{version}` | Historical HMAC keys | Do not delete while fingerprints reference them |
| `projectx/contact-channel/webhook-client-state` | Graph webhook clientState verifier | Rotate if leaked or periodically |
| `projectx/contact-channel/webhook-secret` | Webhook subscription secret | Per-tenant if supported |

## Key Vault Naming Rules

- Use lowercase, hyphen separators.
- Do not include `secret`, `password`, or `key` redundantly in the path beyond what is required.
- Use versioned prefixes for keys that may roll (`...-keys/{version}`).
- Tag each secret with `owner`, `rotation-date`, and `purpose`.
