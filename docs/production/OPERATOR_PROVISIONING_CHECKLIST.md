# ProjectX Operator Provisioning Checklist

## Legend

- **DEVIN CAN DO**: Safe to execute with this deliverable (code, docs, scripts).
- **USER/AZURE ADMIN MUST DO**: Requires an authorized Azure / Microsoft tenant administrator.
- **EXTERNAL PROVIDER MUST DO**: Requires the third-party service (Microsoft, OpenAI, Anthropic, Temporal, etc.) or the customer’s existing contract.

---

## 0. Terraform Remote State Bootstrap

This is a one-time, separate operation. Run it from `infra/production/terraform/bootstrap` before the main ProjectX stack.

- [ ] **USER/AZURE ADMIN MUST DO** — Identify the Entra principal that will run Terraform (`terraform_principal_id`).
- [ ] **DEVIN CAN DO** — Run `terraform -chdir=infra/production/terraform/bootstrap init` then `apply -var="terraform_principal_id=<id>"` to create:
  - dedicated state resource group
  - dedicated storage account (TLS 1.2, no shared keys, blob versioning enabled)
  - private `tfstate` container
  - `Storage Blob Data Contributor` on the storage account for the Terraform principal
- [ ] **DEVIN CAN DO** — Record `resource_group_name`, `storage_account_name`, and `container_name` from `terraform output`.
- [ ] **USER/AZURE ADMIN MUST DO** — Replace `SET_AFTER_BOOTSTRAP` in `infra/production/terraform/providers.tf` with the real storage account name.
- [ ] **DEVIN CAN DO** — Re-initialize the main stack: `terraform -chdir=infra/production/terraform init -backend-config="storage_account_name=<real-name>"`.
- [ ] **DEVIN CAN DO** — Verify the main stack now writes state to the azurerm backend, not local `terraform.tfstate`.

## 1. Azure Subscription & Region

- [ ] **USER/AZURE ADMIN MUST DO** — Provide an Azure subscription with budget approval.
- [ ] **USER/AZURE ADMIN MUST DO** — Select primary region (e.g. `westeurope`, `eastus`, `uaenorth`).
- [ ] **USER/AZURE ADMIN MUST DO** — Confirm approved region for data residency.

## 2. Resource Group & Identity

- [ ] **DEVIN CAN DO** — Run `infra/production/terraform` to create resource group, VNet, and managed identities.
- [ ] **USER/AZURE ADMIN MUST DO** — Grant the deployment service principal or managed identity sufficient rights to create resources in the subscription/resource group.

## 3. Domain & DNS

- [ ] **USER/AZURE ADMIN MUST DO** — Register or delegate a production domain / subdomain (e.g. `projectx.example.com`).
- [ ] **USER/AZURE ADMIN MUST DO** — Create public DNS `A`/`CNAME` record pointing to the API Container App / Application Gateway public IP.
- [ ] **USER/AZURE ADMIN MUST DO** — Provide a TLS certificate or allow Azure to manage it with the free managed cert (Container Apps / App Gateway).

## 4. Azure Key Vault

- [ ] **DEVIN CAN DO** — Provision Key Vault with purge protection, private endpoint, and RBAC.
- [ ] **USER/AZURE ADMIN MUST DO** — Add the API and worker managed identities to the `Key Vault Secrets User` role.
- [ ] **USER/AZURE ADMIN MUST DO** — Generate or import the initial recipient encryption and HMAC keys.
- [ ] **USER/AZURE ADMIN MUST DO** — Add Graph, LLM, embedding, and Dynamics secrets using the exact names in `docs/production/SECRET_INVENTORY.md`.
- [ ] **USER/AZURE ADMIN MUST DO** — Store `DATABASE_URL` and `REDIS` keys generated by Terraform into the vault.

## 5. PostgreSQL Flexible Server

- [ ] **DEVIN CAN DO** — Provision `azurerm_postgresql_flexible_server` with `pgvector` enabled and a private endpoint.
- [ ] **DEVIN CAN DO** — Create `projectx_app` role with `NOBYPASSRLS`, `NOLOGIN`? (Use a regular DB role for application.)
- [ ] **USER/AZURE ADMIN MUST DO** — Create a firewall rule that allows only the private VNet; disable public access.
- [ ] **DEVIN CAN DO** — Store generated connection string in Key Vault.

## 6. Redis

- [ ] **DEVIN CAN DO** — Provision `azurerm_managed_redis` (Azure Managed Redis) with private endpoint and SSL. Use `Balanced_B0` for test/shadow with `high_availability_enabled = false`.
- [ ] **DEVIN CAN DO** — Store host, port, and access key in Key Vault.

## 7. Temporal

- [ ] **EXTERNAL PROVIDER MUST DO / USER MUST DO** — Either:
  - Sign up for Temporal Cloud, create a namespace, generate mTLS certificates, and provide `TEMPORAL_ADDRESS`, `TEMPORAL_NAMESPACE`, cert/key names; OR
  - Provide an AKS/VM cluster where Temporal can be self-hosted.
- [ ] **DEVIN CAN DO** — Configure the worker to connect to the provided Temporal endpoint.

## 8. Microsoft Graph / Exchange

- [ ] **USER/AZURE ADMIN MUST DO** — Register an Entra application.
- [ ] **USER/AZURE ADMIN MUST DO** — Grant `Mail.Send` (application) and related permissions.
- [ ] **EXTERNAL PROVIDER MUST DO** — Microsoft admin consent.
- [ ] **EXTERNAL PROVIDER MUST DO** — Clear any tenant send restriction / EOP allowlist.
- [ ] **USER/AZURE ADMIN MUST DO** — Provide the approved sender mailbox address.
- [ ] **USER/AZURE ADMIN MUST DO** — Configure the Graph webhook callback URL to the public API webhook endpoint.

## 9. Calendar

- [ ] **USER/AZURE ADMIN MUST DO** — Grant `Calendars.ReadWrite` (application) or delegated calendar access.
- [ ] **EXTERNAL PROVIDER MUST DO** — Microsoft admin consent.

## 10. Dynamics 365

- [ ] **USER/AZURE ADMIN MUST DO** — Provide the Dataverse organization URL(s) for the workspace(s).
- [ ] **USER/AZURE ADMIN MUST DO** — Grant `user_impersonation` or application permissions for read-only access.
- [ ] **EXTERNAL PROVIDER MUST DO** — Microsoft admin consent.

## 11. LLM & Embedding

- [ ] **EXTERNAL PROVIDER MUST DO** — Provide Azure OpenAI or OpenAI API access.
- [ ] **EXTERNAL PROVIDER MUST DO** — Provide an embedding model with the exact `dimensions`, `model`, `version`, `provider`, and `distance_metric` documented by the operator.
- [ ] **USER/AZURE ADMIN MUST DO** — Add API keys to Key Vault under the names in `docs/production/SECRET_INVENTORY.md`.

## 12. Container Registry & Images

- [ ] **DEVIN CAN DO** — Provision Azure Container Registry. The test/shadow environment uses Basic SKU with the public endpoint as an explicit cost exception; private endpoints require Premium SKU.
- [ ] **DEVIN CAN DO** — Confirm `admin_enabled = false` and `AcrPull` is assigned to API and worker managed identities.
- [ ] **USER/AZURE ADMIN MUST DO** — Build and push real images before the final apply using immutable digest references or unique release tags:
  1. `docker build -t <acr-name>.azurecr.io/projectx/api:<git-sha> ./apps/api`
  2. `docker build -t <acr-name>.azurecr.io/projectx/worker:<git-sha> ./apps/temporal-worker`
  3. `az acr login -n <acr-name>`
  4. `docker push <acr-name>.azurecr.io/projectx/api:<git-sha>`
  5. `docker push <acr-name>.azurecr.io/projectx/worker:<git-sha>`
- [ ] **DEVIN CAN DO** — Run the final `terraform apply -var="api_image=<acr-name>.azurecr.io/projectx/api:<git-sha>" -var="worker_image=<acr-name>.azurecr.io/projectx/worker:<git-sha>"`.

Do not use `placeholder.invalid/projectx-api:plan-only` or `placeholder.invalid/projectx-worker:plan-only` for apply.

## 13. Deployment

- [ ] **DEVIN CAN DO** — Run the GitHub Actions / pipeline workflow.
- [ ] **DEVIN CAN DO** — Run `scripts/production/bootstrap-migrations.sh` with the operator-supplied `DATABASE_URL`.
- [ ] **DEVIN CAN DO** — Run `scripts/production/smoke-test.sh` against the deployed API.

## 14. Active Embedding Profile

- [ ] **DEVIN CAN DO** — Run the `INSERT` in `docs/production/EMBEDDING_PROFILE_BOOTSTRAP.md` to create exactly one `ACTIVE` profile matching the provided provider/model/version/dimensions.
- [ ] **DEVIN CAN DO** — Restart worker and verify `ValidatedEmbeddingRuntime` succeeds.

## 15. Live-Send Safety

- [ ] **USER/AZURE ADMIN MUST DO** — Confirm `OUTREACH_LIVE_EMAIL_ENABLED=false` and `OUTREACH_MODE=SHADOW` or `ALLOWLIST_ONLY`.
- [ ] **USER/AZURE ADMIN MUST DO** — Approve the certification send list and rate limits before enabling live send.

## Where Secrets Are Entered

1. CI/CD pipeline variables: only non-secret `CONFIG` and `EXTERNAL_PROVIDER` values.
2. Azure Key Vault: all `SECRET` values are entered by the Azure admin through the Azure portal, CLI, or a separate hardened provisioning script.
3. Container App secrets: all secrets are sourced from Key Vault by the application at runtime using the workload managed identity.
4. Terraform variables: only `CONFIG` and resource-naming variables; secret values are generated and stored by the pipeline into Key Vault, not passed as TF variables.
