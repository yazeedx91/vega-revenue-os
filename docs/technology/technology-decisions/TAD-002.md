# TAD-002: TypeScript/Node.js as Primary Backend Stack

- **Decision ID:** TAD-002
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** CTO / Principal Software Architect

## Decision

TypeScript / Node.js is the primary backend language for all application services, workers, API layer, agent orchestration integration, Tool Gateway, integration services, background workers, workflow integration, and event consumers/producers.

## Context

Organizational constraint. TypeScript provides type safety, async I/O, and a large ecosystem.

## Alternatives

- Python (rich AI ecosystem) — allowed only for isolated specialized workloads.
- Go (performance/concurrency) — not required for current workloads.
- C#/.NET (Microsoft ecosystem) — organizational decision to use TypeScript.

## Rationale

TypeScript aligns with organizational skills, enables full-stack type sharing, and has strong support for APIs, events, and tooling.

## Impact

- Consistent language across API, domain, workers, and gateways.
- Node.js event loop suits I/O-bound integration and AI orchestration.
- Python may be used for offline ML/evaluation if isolated.

## Conditions for Reconsideration

A specific workload proves technically inappropriate for TypeScript/Node.js; documented as Proposed ADR with isolation plan.
