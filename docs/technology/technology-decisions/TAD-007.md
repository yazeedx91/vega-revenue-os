# TAD-007: Temporal as Workflow Engine

- **Decision ID:** TAD-007
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Distributed Systems Engineer

## Decision

Temporal is the durable workflow engine for long-running revenue missions.

## Context

Missions can run for weeks and require timers, signals, cancellation, compensation, versioning, and pause/resume.

## Alternatives

- Azure Durable Functions: Azure-native but less flexible for multi-tenant compensation and versioning.
- Cadence: predecessor to Temporal; Temporal has better ecosystem and TypeScript SDK.
- Custom workflow engine: too risky.

## Rationale

Temporal provides robust durable execution, versioning, signals, and multi-language SDKs. The engine can be hosted on Azure Container Apps or AKS, but the production-validated deployment topology is a Phase 07 deliverable, not a default assumption.

## Impact

- Mission orchestration implemented as Temporal workflows.
- Worker hosting candidate is Azure Container Apps; AKS is a validated alternative if operational requirements demand it.
- Persistence in PostgreSQL, visibility in Azure Managed Redis.
- Phase 07 must complete the validation checklist in `/docs/technology/06-workflow-engine.md` before finalizing the platform.

## Conditions for Reconsideration

Operational complexity exceeds team capacity; evaluate managed Temporal or Azure Durable Functions.
