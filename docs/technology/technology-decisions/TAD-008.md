# TAD-008: PostgreSQL pgvector + Azure AI Search for Vector/Hybrid Retrieval

- **Decision ID:** TAD-008
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Data Architect / AI Infrastructure Architect

## Decision

Use PostgreSQL pgvector for initial vector storage; add Azure AI Search for hybrid retrieval and scale when needed.

## Context

The system needs semantic memory and knowledge retrieval. Starting simple avoids extra infrastructure.

## Alternatives

- Dedicated vector DB (Pinecone, Weaviate): adds operational complexity and cost.
- Azure AI Search only: powerful but overkill for initial scale.
- Elasticsearch: not Azure-native.

## Rationale

pgvector in the existing PostgreSQL database covers early needs. Azure AI Search provides a clear scale path for hybrid search and re-ranking.

## Impact

- Single database for transactional and vector data initially.
- Migration path to Azure AI Search documented.

## Conditions for Reconsideration

Vector query performance or scale exceeds pgvector capabilities.
