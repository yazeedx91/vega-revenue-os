# TAD-016: Azure Container Apps as Primary Runtime Platform

- **Decision ID:** TAD-016
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Cloud Architect / Platform Architect

## Decision

Azure Container Apps is the primary runtime platform for API, workers, AI execution, and integration gateways.

## Context

The modular monolith + worker pool architecture requires managed container hosting with autoscaling and low operational overhead.

## Alternatives

- AKS: more control but higher operational complexity.
- Azure Functions: limited for multi-container and AI runtime needs.
- Azure App Service: less suited for worker/scaling patterns.

## Rationale

Container Apps provides KEDA scaling, Dapr, VNet integration, and lower operations cost than AKS.

## Impact

- Faster time to production.
- Event-driven scaling from Service Bus.
- Path to AKS documented for future scale.

## Conditions for Reconsideration

Networking, scale, or specialized compute needs exceed Container Apps capabilities.
