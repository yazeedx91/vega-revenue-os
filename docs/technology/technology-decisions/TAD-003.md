# TAD-003: NestJS as Backend Framework

- **Decision ID:** TAD-003
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Principal Software Architect

## Decision

NestJS is the primary application framework for the TypeScript backend.

## Context

The architecture requires modular, DDD-aligned services with dependency injection, OpenAPI, testing, and background worker support.

## Alternatives

- Fastify + custom DI: higher performance but more custom code.
- Express + custom: too low-level; requires building too much.
- AdonisJS: full-stack focused, less suitable.

## Rationale

NestJS provides modules, DI, decorators, built-in OpenAPI, testing utilities, and a clear path from modular monolith to microservices.

## Impact

- Bounded contexts map to NestJS modules.
- Controllers for REST APIs, event handlers for Service Bus, providers for adapters.
- Easy integration with BullMQ, TypeORM/Prisma, OpenTelemetry.

## Conditions for Reconsideration

Team experience or performance requirements make NestJS unsuitable; documented.
