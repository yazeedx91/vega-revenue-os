# TAD-005: Azure Managed Redis as Cache

- **Decision ID:** TAD-005
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Principal Software Architect

## Decision

Azure Managed Redis is the distributed cache. Azure Cache for Redis is retained only as a legacy or migration alternative.

## Context

Needed for session state, tenant config, rate limiting, idempotency, distributed locks, and hot data caching.

## Alternatives

- Azure Cache for Redis: retained only for legacy or migration scenarios; not the canonical production choice.
- Self-hosted Redis: operational burden.
- Azure Cosmos DB as cache: overkill and costly.
- In-memory caching only: not suitable for multi-instance deployment.

## Rationale

Azure Managed Redis offers low-latency, distributed caching, pub/sub, distributed locks, persistence, active-geo replication, and low operational overhead. It is the managed Redis service aligned with the Azure-first strategy.

## Impact

- Tenant-scoped keys enforce isolation.
- Supports idempotency, rate limiting, and locks.
- Active-geo for DR available.
