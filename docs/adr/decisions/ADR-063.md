# ADR-063: Prompt Injection Defenses

- **ADR ID:** ADR-063
- **Status:** Accepted
- **Group:** Security
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear security direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the prompt injection defenses concern.

## Problem

Multiple security options exist for prompt injection defenses. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Validate inputs
- separate control from data
- sandbox outputs

## Decision

Use prompt boundaries, input validation, role separation, output sandboxing, and allowlisting to mitigate prompt injection.

## Alternatives

1. **Trust user inputs**
2. **No LLM access**

## Rationale

A layered defense reduces the chance and impact of prompt injection without eliminating the value of LLM integration.

## Consequences

This decision aligns the security domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Sophisticated attacks
- false positives

## Mitigations

- Red team exercises
- defense-in-depth
- monitoring

## Security Impact

This decision is itself a security control; it sets the boundary for identity, authorization, encryption, and audit.

## Performance Impact

Fine-grained authorization is enforced closest to the data to avoid repeated policy checks in every layer.

## Scalability Impact

Tenant-scoped tokens and claims scale with the identity provider and are cacheable.

## Cost Impact

Reusing standards (OAuth2/OIDC, KMS, TLS) avoids custom security implementations and compliance rework.

## Operational Impact

Centralized auth, audit, and secret management reduce operational toil and incident response time.

## AI Impact

Model calls are gated by permission checks, ensuring agents cannot access cross-tenant data or privileged actions.

## Reversibility

Medium. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
