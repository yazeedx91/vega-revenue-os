# ADR-117: Phase 14 Objective and Scope

- **ADR ID:** ADR-117
- **Status:** Proposed
- **Group:** Phase Planning / Architecture
- **Date:** 2026-08-13
- **Decision Owners:** Architecture Review Board, CTO, Engineering Leads

## Context

Phases 09–13 established the domain model, AI execution contract, mission orchestration, revenue intelligence, outreach execution kernel, and conversation handling. The system can execute a deterministic end-to-end pipeline, but it has no durable persistence and no real external communication channel. Phase 14 must select the highest-leverage next capability that advances real-world autonomy while fixing foundational operational gaps.

## Decision

1. Phase 14 will implement **production email integration** using Microsoft Graph / Exchange Online as the only new external communication channel.
2. Phase 14 will **not** implement Dynamics 365 CRM write-back, calendar/meeting booking, LinkedIn messaging, real LLM personalization, public UI, or multi-provider email.
3. Phase 14 will introduce durable persistence, secrets management, audit/event persistence, and rate limiting because they are prerequisites for real external email.
4. Phase 14 will keep intelligence/research providers as stubs; the email channel is the only real outbound integration.

## Alternatives

1. **Persistence hardening only.** Rejected: does not change what the system can do, making validation harder and delaying customer value.
2. **Dynamics 365 CRM write-back first.** Rejected: ARB deferred write-back; without a real communication channel there are no email activities to write.
3. **Autonomous learning/ML loop first.** Rejected: no production data stream exists yet; premature optimization.
4. **Observability/control plane first.** Rejected: valuable but secondary; there is no durable data to observe.

## Rationale

Email is the primary outbound channel in the revenue workflow. Implementing it forces the team to solve persistence, secrets, tenant isolation, audit, idempotency, approval boundaries, and workflow completion simultaneously. Restricting the rollout to an allowlist keeps the risk bounded.

## Consequences

- ProjectX moves from simulation to real (allowlist-restricted) customer contact.
- PostgreSQL/Redis and a secrets provider become mandatory infrastructure.
- Security, compliance, and operations become first-class concerns.
- Future phases can add CRM write-back, calendar, and additional providers on top of the email foundation.
