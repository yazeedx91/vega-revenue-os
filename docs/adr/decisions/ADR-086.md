# ADR-086: API and Schema Governance

- **ADR ID:** ADR-086
- **Status:** Accepted
- **Group:** Governance
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear governance direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the api and schema governance concern.

## Problem

Multiple governance options exist for api and schema governance. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Register schemas
- gate breaking changes
- support review

## Decision

Maintain a central schema registry, require OpenAPI/AsyncAPI review, and gate breaking changes.

## Alternatives

1. **Ad-hoc schemas**
2. **No schema governance**

## Rationale

Centralized schema governance prevents accidental breaking changes and improves consumer onboarding.

## Consequences

This decision aligns the governance domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Bureaucracy
- slow changes

## Mitigations

- Automated compatibility checks
- tiered review

## Security Impact

Governance processes enforce that security, privacy, and compliance are considered in every ADR and feature.

## Performance Impact

Versioned APIs and clear lifecycles let consumers plan migrations, reducing upgrade churn.

## Scalability Impact

Governance by contract lets multiple teams work in parallel without destabilizing shared services.

## Cost Impact

Predictable deprecation and versioning avoid costly fire-drills and backward-compatibility hacks.

## Operational Impact

ADRs, runbooks, and clear ownership reduce tribal knowledge and improve change management.

## AI Impact

Governance defines when an AI may act autonomously and when human approval is mandatory.

## Reversibility

Medium. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
