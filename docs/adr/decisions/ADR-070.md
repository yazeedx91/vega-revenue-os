# ADR-070: Tenant Offboarding and Data Destruction

- **ADR ID:** ADR-070
- **Status:** Proposed
- **Group:** Security
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear security direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the tenant offboarding and data destruction concern.

## Problem

Multiple security options exist for tenant offboarding and data destruction. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Delete or export tenant data
- provide certificates
- audit

## Decision

Automated offboarding workflow that exports or deletes data per policy and provides a certificate of destruction.

## Alternatives

1. **Manual deletion**
2. **Immediate hard delete without confirmation**

## Rationale

An automated workflow ensures consistent, auditable, and compliant data destruction when tenants leave.

## Consequences

This decision aligns the security domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Data remnant
- accidental deletion

## Mitigations

- Data maps
- soft delete first
- certificate generation

## Security Impact

This decision is itself a security control; it sets the boundary for identity, authorization, encryption, and audit.

## Performance Impact

Fine-grained authorization is enforced closest to the data to avoid repeated policy checks in every layer.

## Scalability Impact

Tenant-scoped tokens and claims scale with the identity provider and are cacheable.

## Cost Impact

Reusing standards (OAuth2/OIDC, KMS, TLS) avoids custom security implementations and compliance rework.

## Operational Impact

Centralized auth, audit, and secret management reduce operational toil and incident response time.

## AI Impact

Model calls are gated by permission checks, ensuring agents cannot access cross-tenant data or privileged actions.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
