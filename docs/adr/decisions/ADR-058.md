# ADR-058: Data Encryption at Rest and In Transit

- **ADR ID:** ADR-058
- **Status:** Accepted
- **Group:** Security
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear security direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the data encryption at rest and in transit concern.

## Problem

Multiple security options exist for data encryption at rest and in transit. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Encrypt all data in transit and at rest
- protect tenant data

## Decision

Use TLS for all transit, AES-256 or cloud-managed encryption at rest, and envelope encryption for tenant data.

## Alternatives

1. **Encryption only in transit**
2. **No encryption**

## Rationale

Layered encryption protects against network and storage compromise and supports compliance requirements.

## Consequences

This decision aligns the security domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Key management complexity
- performance overhead

## Mitigations

- Hardware-backed KMS
- connection pooling
- encryption benchmarks

## Security Impact

This decision is itself a security control; it sets the boundary for identity, authorization, encryption, and audit.

## Performance Impact

Fine-grained authorization is enforced closest to the data to avoid repeated policy checks in every layer.

## Scalability Impact

Tenant-scoped tokens and claims scale with the identity provider and are cacheable.

## Cost Impact

Reusing standards (OAuth2/OIDC, KMS, TLS) avoids custom security implementations and compliance rework.

## Operational Impact

Centralized auth, audit, and secret management reduce operational toil and incident response time.

## AI Impact

Model calls are gated by permission checks, ensuring agents cannot access cross-tenant data or privileged actions.

## Reversibility

Medium. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
