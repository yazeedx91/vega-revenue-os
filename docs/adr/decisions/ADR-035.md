# ADR-035: LLM Observability

- **ADR ID:** ADR-035
- **Status:** Proposed
- **Group:** AI
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear ai direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the llm observability concern.

## Problem

Multiple ai options exist for llm observability. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Trace model calls
- meter token usage
- detect failures
- stay vendor-neutral

## Decision

Use OpenTelemetry plus LLM-specific observability to trace prompts, completions, token usage, latency, errors, and cost per tenant.

## Alternatives

1. **No observability of LLM calls**
2. **Vendor-specific observability only**

## Rationale

OpenTelemetry and custom LLM spans give a unified, vendor-neutral view of model behavior and cost, which is critical for debugging and billing.

## Consequences

This decision aligns the ai domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Sensitive prompt data in traces
- high telemetry volume

## Mitigations

- Data redaction
- sampling
- retention policies
- encrypted trace store

## Security Impact

Provider keys, prompt data, and outputs are isolated per tenant; all high-impact actions require explicit approval.

## Performance Impact

Model routing and caching reduce both latency and cost by selecting the smallest capable model for the task.

## Scalability Impact

A multi-provider abstraction and tool registry let us add models and capabilities without core rewrites.

## Cost Impact

Usage is metered per tenant; cheaper models handle routine tasks and expensive models are reserved for complex reasoning.

## Operational Impact

Prompt versioning, model health checks, and fallback chains make AI services observable and maintainable.

## AI Impact

Structured output, confidence scoring, and citations are first-class concerns, directly improving agent reliability.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
