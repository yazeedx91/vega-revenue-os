# ADR-098: Dynamics 365 Intelligence Boundary — Port and Stub Only

- **ADR ID:** ADR-098
- **Status:** Accepted
- **Group:** Integrations / CRM
- **Date:** 2026-08-09
- **Decision Owners:** Architecture Board, CTO

## Context

Phase 11 is optimized for Microsoft Dynamics 365 ERP. Live read/write APIs require tenant credentials and a sandbox; these are not available for this phase. We still need a clean boundary so future work can connect to the real Web API without touching business logic.

## Decision

1. Define a tenant-scoped port `IDynamicsIntelligenceAdapter` in `packages/intelligence` for read-only lookup operations (accounts, contacts, duplicates).
2. Implement a deterministic stub adapter `StubDynamicsIntelligenceAdapter` seeded with test data.
3. Do **not** implement real HTTP calls, OAuth flows, or write-back in Phase 11.
4. Keep the adapter behind the existing `ToolCallRequest` authorization path when called from agents.

## Alternatives

1. Build a full Dynamics 365 Web API client now. Rejected: no sandbox credentials, and Phase 11 is about intelligence logic, not integration plumbing.
2. Skip the port and hard-code stub behavior. Rejected: a real port makes the eventual API integration a drop-in replacement.

## Rationale

A stable port with a stub adapter lets the team validate data flow, duplicate detection, and tenant isolation before external credentials are provisioned.

## Consequences

- The pipeline can run end-to-end without external dependencies.
- Future Dynamics 365 work only needs a new adapter implementation.

## Risks

- The stub may not expose all real-world edge cases (throttling, pagination, entitlement checks). These will be handled in the real adapter.

## Security Impact

No credentials are stored or transmitted. Tenant-scoped lookup avoids cross-tenant leakage.

## Performance Impact

Stub lookups are in-memory and fast. The real adapter will add network latency and must include caching.

## Scalability Impact

None in Phase 11.

## Cost Impact

None.

## Operational Impact

None.

## AI Impact

Agents can reference existing Dynamics records safely via a controlled adapter.

## Reversibility

High. Replacing the stub with a real adapter requires no business-logic changes.

## Addendum (2026-08-17, Phase 13.5)

Per `ADR-125`, `IDynamicsIntelligenceAdapter` was renamed to `IBusinessSystemIntelligenceAdapter` and `StubDynamicsIntelligenceAdapter` to `DynamicsIntelligenceAdapterStub` (`packages/intelligence`). This is a pure rename reflecting that Dynamics 365 is the first connector behind a provider-neutral port, not a change to this ADR's original decision, stub behavior, or scope boundary (still read-only, still no live HTTP/OAuth in this phase).
