# ADR-074: Cloud Provider and Region Strategy

- **ADR ID:** ADR-074
- **Status:** Proposed
- **Group:** Platform
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear platform direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the cloud provider and region strategy concern.

## Problem

Multiple platform options exist for cloud provider and region strategy. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Avoid lock-in
- support major clouds
- choose based on preference

## Decision

Remain cloud-agnostic with containers and IaC; default evaluation targets are AWS, Azure, and GCP; choose based on organizational preference.

## Alternatives

1. **Single cloud from day one**
2. **Multi-cloud active-active everywhere**

## Rationale

Cloud-agnostic design preserves optionality. A single provider can be selected for initial focus, but nothing is hard-wired.

## Consequences

This decision aligns the platform domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Least-common-denominator features
- abstraction overhead

## Mitigations

- Provider-specific modules
- portability tests
- cost analysis

## Security Impact

Container and infrastructure controls (image scanning, network policies, least-privilege service accounts) protect the runtime.

## Performance Impact

Managed or operator-based services provide autoscaling, fast storage, and global load balancing.

## Scalability Impact

Cloud-agnostic containers and declarative infrastructure allow moving between regions and providers.

## Cost Impact

Kubernetes-ready but not required on day one; we can start on managed containers and migrate when cost-effective.

## Operational Impact

Infrastructure as code, GitOps, and automated pipelines make changes traceable and reversible.

## AI Impact

GPU or inference-specific workloads can be scheduled on dedicated nodes without rewriting the platform contract.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
