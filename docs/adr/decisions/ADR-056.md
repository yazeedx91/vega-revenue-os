# ADR-056: Tenant-Scoped Roles and Permissions

- **ADR ID:** ADR-056
- **Status:** Accepted
- **Group:** Security
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear security direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the tenant-scoped roles and permissions concern.

## Problem

Multiple security options exist for tenant-scoped roles and permissions. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Scope roles by tenant
- enforce at every layer
- support admin delegation

## Decision

Role definitions and JWT claims carry tenant ID and are enforced at the API gateway, service, and database layers.

## Alternatives

1. **Global roles**
2. **Per-tenant custom policy engine**

## Rationale

Tenant-scoped roles keep authorization simple, auditable, and consistent across the stack.

## Consequences

This decision aligns the security domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Claim sprawl
- stale roles

## Mitigations

- Role registry
- automated tests
- least privilege

## Security Impact

This decision is itself a security control; it sets the boundary for identity, authorization, encryption, and audit.

## Performance Impact

Fine-grained authorization is enforced closest to the data to avoid repeated policy checks in every layer.

## Scalability Impact

Tenant-scoped tokens and claims scale with the identity provider and are cacheable.

## Cost Impact

Reusing standards (OAuth2/OIDC, KMS, TLS) avoids custom security implementations and compliance rework.

## Operational Impact

Centralized auth, audit, and secret management reduce operational toil and incident response time.

## AI Impact

Model calls are gated by permission checks, ensuring agents cannot access cross-tenant data or privileged actions.

## Reversibility

Medium. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
