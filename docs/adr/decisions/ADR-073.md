# ADR-073: Infrastructure as Code

- **ADR ID:** ADR-073
- **Status:** Proposed
- **Group:** Platform
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear platform direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the infrastructure as code concern.

## Problem

Multiple platform options exist for infrastructure as code. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Automate infrastructure
- version control
- peer review

## Decision

Use Terraform or Pulumi to define all infrastructure, store state securely, and enforce peer review.

## Alternatives

1. **Manual cloud console**
2. **Vendor-specific IaC only**

## Rationale

IaC makes infrastructure reproducible, auditable, and testable across environments and cloud providers.

## Consequences

This decision aligns the platform domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- State management
- secret handling
- drift

## Mitigations

- Remote state with locking
- encrypted values
- drift detection

## Security Impact

Container and infrastructure controls (image scanning, network policies, least-privilege service accounts) protect the runtime.

## Performance Impact

Managed or operator-based services provide autoscaling, fast storage, and global load balancing.

## Scalability Impact

Cloud-agnostic containers and declarative infrastructure allow moving between regions and providers.

## Cost Impact

Kubernetes-ready but not required on day one; we can start on managed containers and migrate when cost-effective.

## Operational Impact

Infrastructure as code, GitOps, and automated pipelines make changes traceable and reversible.

## AI Impact

GPU or inference-specific workloads can be scheduled on dedicated nodes without rewriting the platform contract.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
