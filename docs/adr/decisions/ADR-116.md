# ADR-116: Persistence Deferral for Phase 13

- **ADR ID:** ADR-116
- **Status:** Proposed
- **Group:** Data / Infrastructure
- **Date:** 2026-08-12
- **Decision Owners:** Architecture Review Board, CTO

## Context

All repositories in Phases 08–12 are in-memory doubles. Phase 13 adds a new bounded context that needs persistence boundaries but not a production database yet.

## Decision

1. Phase 13 will not introduce concrete persistence adapters.
2. Define repository ports for `Conversation` and the conversation-scoped `Lead` view.
3. Provide in-memory implementations with tenant isolation and idempotency guarantees.
4. Defer PostgreSQL/event-store migration, schema design, and migration tooling to a dedicated Phase 14 persistence foundation.

## Alternatives

1. Add PostgreSQL for all aggregates now. Rejected: splits focus, introduces schema and operations work before the conversation domain model is validated.
2. Add an event store now. Rejected: event-sourcing infrastructure is a large, cross-cutting concern that deserves its own phase.

## Rationale

Validating the conversation domain and autonomy boundaries with in-memory doubles keeps Phase 13 focused and reduces rework risk when persistence is introduced later.

## Consequences

- State is not durable across process restarts.
- Repository interfaces must be designed to map cleanly to a future relational/event-store implementation.
