# ADR-032: Retrieval-Augmented Generation

- **ADR ID:** ADR-032
- **Status:** Proposed
- **Group:** AI
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear ai direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the retrieval-augmented generation concern.

## Problem

Multiple ai options exist for retrieval-augmented generation. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Ground answers in tenant data
- support external facts
- reduce hallucination

## Decision

Use RAG over pgvector, web search results, and knowledge graph to ground LLM responses in tenant data and external facts.

## Alternatives

1. **Rely entirely on model parametric knowledge**
2. **Vector-only retrieval with no external search**

## Rationale

RAG improves accuracy, reduces hallucination, and lets the system answer from private tenant data. Combining vector, search, and graph improves coverage.

## Consequences

This decision aligns the ai domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Retrieval noise
- stale documents
- retrieval latency

## Mitigations

- Relevance scoring
- re-ranking
- freshness filters
- caching

## Security Impact

Provider keys, prompt data, and outputs are isolated per tenant; all high-impact actions require explicit approval.

## Performance Impact

Model routing and caching reduce both latency and cost by selecting the smallest capable model for the task.

## Scalability Impact

A multi-provider abstraction and tool registry let us add models and capabilities without core rewrites.

## Cost Impact

Usage is metered per tenant; cheaper models handle routine tasks and expensive models are reserved for complex reasoning.

## Operational Impact

Prompt versioning, model health checks, and fallback chains make AI services observable and maintainable.

## AI Impact

Structured output, confidence scoring, and citations are first-class concerns, directly improving agent reliability.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
