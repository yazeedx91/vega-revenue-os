# ADR-036: Prompt Versioning and Management

- **ADR ID:** ADR-036
- **Status:** Proposed
- **Group:** AI
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear ai direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the prompt versioning and management concern.

## Problem

Multiple ai options exist for prompt versioning and management. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Version prompts
- enable rollbacks
- support A/B tests
- parameterize

## Decision

Store prompt templates in source control with version tags, parameter injection, and A/B test gates; deploy prompts like code.

## Alternatives

1. **Prompts in database only without version control**
2. **No prompt management**

## Rationale

Versioning prompts with code enables rollbacks, reviews, and reproducibility. A/B gates support systematic improvement.

## Consequences

This decision aligns the ai domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Prompt proliferation
- deployment coupling

## Mitigations

- Naming conventions
- review gates
- feature flags for prompt variants

## Security Impact

Provider keys, prompt data, and outputs are isolated per tenant; all high-impact actions require explicit approval.

## Performance Impact

Model routing and caching reduce both latency and cost by selecting the smallest capable model for the task.

## Scalability Impact

A multi-provider abstraction and tool registry let us add models and capabilities without core rewrites.

## Cost Impact

Usage is metered per tenant; cheaper models handle routine tasks and expensive models are reserved for complex reasoning.

## Operational Impact

Prompt versioning, model health checks, and fallback chains make AI services observable and maintainable.

## AI Impact

Structured output, confidence scoring, and citations are first-class concerns, directly improving agent reliability.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
