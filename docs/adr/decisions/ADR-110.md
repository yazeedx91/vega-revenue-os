# ADR-110: Evidence-Backed Personalization and Output Validation

- **ADR ID:** ADR-110
- **Status:** Proposed
- **Group:** AI / Outreach
- **Date:** 2026-08-12
- **Decision Owners:** Architecture Review Board, CTO

## Context

AI-generated outreach must be personalized but must not fabricate facts, leak PII, violate policy, or make unsupported claims. Phase 11 already provides evidence provenance; Phase 12 must consume it during personalization.

## Decision

1. `OutreachPersonalizationService` uses the existing `ai-runtime` reasoning and output-validation components:
   - `LLMReasoningEngine` or `IAgentExecutor` for draft generation.
   - `IOutputValidator` for PII, brand, compliance, and schema validation.
   - `IPolicyClient` for policy decisions.
2. The prompt context is built only from verified `ResearchEvidence` with provenance entries.
3. Every factual claim in the generated draft is extracted and matched against evidence references.
4. Unsupported claims are removed; drafts with policy/PII violations are rejected.
5. The validated `MessageDraft` value object carries:
   - Subject, body, CTA, tone.
   - A `claimList` with `(text, evidenceId, confidence)`.
   - Provenance chain from planning → reasoning → validation.
   - Policy/validation outcome references.

## Alternatives

1. Allow the LLM to reference any context and rely on human approval to catch fabrications. Rejected: unsafe and non-deterministic.
2. Build a separate LLM abstraction just for outreach. Rejected: duplicates `ai-runtime` capabilities and fragments model/policy management.

## Rationale

Reusing the generic AI runtime for generation and validation while adding a claim-verification layer on top keeps the system coherent, auditable, and aligned with the evidence model.

## Consequences

- Outreach drafts are explainable down to evidence references.
- PII/policy checks are applied consistently across all AI outputs.
- The personalization service is testable without real LLM calls.

## Risks

- Claim extraction may be imperfect; fallback is to require human review for ambiguous claims.
- Strict evidence matching may reduce personalization quality; tenant-configurable thresholds can balance safety and quality.

## Security Impact

PII is caught by the existing output validator; unsupported facts are removed before any message can be approved.

## Performance Impact

Draft generation and validation are cheaper than provider sends but add latency; results are not cached by default to allow policy evolution.

## Scalability Impact

Generation can be parallelized per recipient.

## Cost Impact

Low; mostly LLM token cost during drafting.

## Operational Impact

Operators can inspect a draft’s claim list and evidence references for compliance reviews.

## AI Impact

Forces AI-generated outreach to be grounded in evidence and policy rather than open-ended generation.

## Reversibility

Medium. The claim-verification contract becomes part of the `MessageDraft` value object; changes affect drafts but not provider contracts.
