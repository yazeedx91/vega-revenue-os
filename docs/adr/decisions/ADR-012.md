# ADR-012: Operational Database

- **ADR ID:** ADR-012
- **Status:** Proposed
- **Group:** Data
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear data direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the operational database concern.

## Problem

Multiple data options exist for operational database. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Support relational and vector data
- enforce tenant isolation
- provide backups and recovery

## Decision

Use PostgreSQL as the primary operational database with row-level security and per-tenant schemas for strong isolation.

## Alternatives

1. **MySQL**
2. **Multi-document NoSQL store as primary**

## Rationale

PostgreSQL is cloud-agnostic, has strong relational semantics, supports row-level security, and can host vectors with pgvector.

## Consequences

This decision aligns the data domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Operational expertise
- write scalability limits
- managed service cost

## Mitigations

- Managed PostgreSQL or Kubernetes operator
- read replicas
- connection pooling
- sharding plan

## Security Impact

PostgreSQL row-level security, encryption at rest/in transit, and tenant-isolated schemas keep per-tenant data separated.

## Performance Impact

A single operational store with proper indexing, read replicas, and connection pooling supports the common workload efficiently.

## Scalability Impact

PostgreSQL scales vertically and through read replicas; polyglot extensions are introduced only when a clear bottleneck is measured.

## Cost Impact

Using one primary engine reduces licensing and operational overhead compared to a cluster of specialized stores.

## Operational Impact

Managed PostgreSQL or operator-based deployments provide backups, point-in-time recovery, and observability.

## AI Impact

pgvector and JSONB allow documents, vectors, and relational facts to coexist, simplifying retrieval and context assembly.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
