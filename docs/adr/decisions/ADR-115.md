# ADR-115: Deterministic Feedback Loop for Outreach Outcomes

- **ADR ID:** ADR-115
- **Status:** Proposed
- **Group:** Conversation / Intelligence
- **Date:** 2026-08-12
- **Decision Owners:** Architecture Review Board, CTO

## Context

The system needs to learn from outreach outcomes (replies, opt-outs, meetings, disqualifications) before introducing machine learning. Phase 13 must record outcomes in a deterministic, auditable way.

## Decision

1. Use a deterministic, rule-based feedback policy in Phase 13.
2. Capture a `ConversationOutcome` record with intent, confidence, action taken, lead status change, and optional human override.
3. Adjust future thresholds and suppression rules based on accumulated outcomes, not model training.
4. Emit domain events (`ConversationClosed`, `LeadReQualified`, `LeadDisqualified`) for downstream consumers.
5. Defer ML/embedding-based learning until the outcome corpus is large enough to justify model complexity.

## Alternatives

1. Introduce a vector store and similarity search for replies now. Rejected: premature; deterministic rules provide explainable behavior with less infrastructure.
2. Fine-tune an LLM on outcomes. Rejected: insufficient data and no operational MLOps pipeline.

## Rationale

Rule-based feedback gives immediate, testable learning behavior and builds the event stream that future ML will consume.

## Consequences

- Feedback logic is easy to audit but less nuanced than a trained model.
- The event schema must remain stable to avoid breaking future ML consumers.
