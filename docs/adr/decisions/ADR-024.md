# ADR-024: Model Routing and Fallback

- **ADR ID:** ADR-024
- **Status:** Proposed
- **Group:** AI
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear ai direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the model routing and fallback concern.

## Problem

Multiple ai options exist for model routing and fallback. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Select by task
- provide fallback
- respect tenant preference
- meter usage

## Decision

Implement a model router that selects provider and model based on task complexity, cost target, latency budget, and tenant preference.

## Alternatives

1. **Hard-coded model for all calls**
2. **Manual human selection per model call**

## Rationale

Routing optimizes cost and quality while enabling graceful fallback when a provider is degraded.

## Consequences

This decision aligns the ai domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Suboptimal routing
- cascading failures
- provider quota limits

## Mitigations

- Benchmark suite
- health checks
- circuit breakers
- quota monitoring

## Security Impact

Provider keys, prompt data, and outputs are isolated per tenant; all high-impact actions require explicit approval.

## Performance Impact

Model routing and caching reduce both latency and cost by selecting the smallest capable model for the task.

## Scalability Impact

A multi-provider abstraction and tool registry let us add models and capabilities without core rewrites.

## Cost Impact

Usage is metered per tenant; cheaper models handle routine tasks and expensive models are reserved for complex reasoning.

## Operational Impact

Prompt versioning, model health checks, and fallback chains make AI services observable and maintainable.

## AI Impact

Structured output, confidence scoring, and citations are first-class concerns, directly improving agent reliability.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
