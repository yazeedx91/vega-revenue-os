# ADR-131: Single Dedicated Microsoft Graph Test Tenant for First Real Send

- **ADR ID:** ADR-131
- **Status:** Accepted
- **Group:** Phase 14.8a / Security / Identity
- **Date:** 2026-08-18
- **Decision Owners:** Architecture Review Board, Security Engineering, Platform Operations

## Context

Phase 14.8 wires the real `GraphEmailProvider` and `FetchGraphInboundMessageFetcher` into the production composition roots. Before the first controlled real email send, the project must decide how Microsoft Graph / Exchange Online credentials will be scoped. The options were:

1. **Option A: Single dedicated Entra ID tenant and application registration** used exclusively for the first controlled send.
2. **Option B: Shared production tenant with restricted permissions and delegated mailbox**.
3. **Option C: Certificate-based authentication with a managed identity in the production cloud subscription**.

## Decision

Adopt **Option A: a single dedicated test tenant / Entra application** for the first real send.

### Required configuration surface

| Variable | Source | Purpose |
|----------|--------|---------|
| `GRAPH_TENANT_ID` | Environment / Key Vault reference | Entra ID tenant that owns the application |
| `GRAPH_CLIENT_ID` | Environment / Key Vault reference | Application (client) ID of the dedicated app registration |
| `GRAPH_CLIENT_SECRET` | Direct environment secret OR `GRAPH_CLIENT_SECRET_REFERENCE` Key Vault reference | Client credential for the client-credentials flow |
| `GRAPH_SENDER_ADDRESS` | Environment | Shared mailbox / sender identity for the test tenant |

### Operational rules

1. The tenant is used exclusively for the first allowlisted real send and reply-correlation validation.
2. The Entra application is granted only `Mail.Send` (Application permission) and `User.Read.All` only if required for subscription resolution; no broader Graph permissions.
3. Admin consent is performed and documented; delegated user permissions are avoided to keep the flow non-interactive and auditable.
4. The client secret is never committed to source control; it is injected via `EnvironmentSecretsProvider` or `AzureKeyVaultSecretsProvider` at runtime.
5. The allowlist for the first send contains exactly one recipient under the test team's control.
6. The tenant must be decommissioned or demoted to non-production after the first send is proven, per a follow-up ARB review.

## Alternatives

1. **Option B — shared production tenant.** Rejected: increases blast radius and makes a mistake on the first send potentially visible to production users. It also complicates allowlist containment because production directory objects could be selected inadvertently.
2. **Option C — managed identity / certificate auth in production subscription.** Rejected: introduces production cloud infrastructure and credential lifecycle work before the basic Graph send/reply loop is proven. Certificate rotation, identity federation, and network isolation are out of scope for Phase 14.8a.

## Rationale

A dedicated test tenant provides the smallest blast radius, the simplest credential rotation story, and a clear audit boundary. It supports the `ALLOWLIST_ONLY` mode in ADR-129 without requiring changes to production directory objects. When the first send succeeds, the same code path and secret-provider abstractions can be retargeted to Option B or C without architectural change.

## Consequences

- A new Entra tenant must be provisioned before GO.
- The environment secret surface now includes Graph-specific variables; they must be present in all production-like deployments.
- `MsalTokenProvider` must be configured with the tenant-specific values; it already supports client-credentials flow via `@azure/msal-node`.
- The `GraphEmailProvider` kill-switch (`OUTREACH_LIVE_EMAIL_ENABLED`) remains the final gate; missing or test-only credentials will cause health checks to fail but will not allow an unauthorized send.

## Security Impact

- Client secret must be stored in a secrets manager and rotated on a schedule.
- The application registration must have no redirect URIs, no implicit flows, and no other delegated permissions.
- Conditional Access should restrict token usage to the expected IP ranges / managed runtime environments.
- All token acquisition and send events must be logged and traced.

## Dependencies

- `ADR-117`: Microsoft Graph as the only email provider
- `ADR-129`: Controlled Communication Enablement Mode (`ALLOWLIST_ONLY`)
- `ADR-127`: Secrets provider abstraction
