# ADR-038: Email and Calendar Adapter

- **ADR ID:** ADR-038
- **Status:** Proposed
- **Group:** Integrations
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear integrations direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the email and calendar adapter concern.

## Problem

Multiple integrations options exist for email and calendar adapter. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Send and receive email
- manage calendar
- support future providers

## Decision

Use Microsoft Graph as the primary email and calendar adapter, abstracted behind a provider interface for future IMAP/SMTP or Google support.

## Alternatives

1. **Use IMAP/SMTP directly**
2. **Hard-code Exchange Online**

## Rationale

Microsoft Graph provides a unified, secure API for enterprise tenants, while the adapter interface keeps the door open for other providers.

## Consequences

This decision aligns the integrations domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Graph API limits
- multi-tenant consent

## Mitigations

- Throttling
- incremental sync
- delegated permissions

## Security Impact

Provider adapters normalize external systems behind domain ports; credentials and tokens are stored in a secrets manager.

## Performance Impact

Caching, idempotency keys, and rate-limiting adapters protect downstream APIs from burst traffic.

## Scalability Impact

New CRM/ERP/email/calendar providers are added as additional adapters, not core changes.

## Cost Impact

Standardized adapters avoid bespoke integrations and enable reuse across tenants.

## Operational Impact

Adapter health and retry metrics are observable; failures are contained within the integration bounded context.

## AI Impact

The intelligence layer receives normalized domain objects, so prompts and planning logic remain provider-agnostic.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
