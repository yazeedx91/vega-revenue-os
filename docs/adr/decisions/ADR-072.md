# ADR-072: Orchestration and Deployment Target

- **ADR ID:** ADR-072
- **Status:** Proposed
- **Group:** Platform
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear platform direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the orchestration and deployment target concern.

## Problem

Multiple platform options exist for orchestration and deployment target. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Deploy to managed platform
- support future Kubernetes

## Decision

Be Kubernetes-ready from day one but start on a managed container platform; migrate to Kubernetes when scale justifies it.

## Alternatives

1. **Kubernetes day one**
2. **Serverless functions only**

## Rationale

Managed containers reduce day-one operational burden while Kubernetes readiness gives a clear scale path.

## Consequences

This decision aligns the platform domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Migration effort
- vendor lock-in

## Mitigations

- Container standards
- environment parity
- migration plan

## Security Impact

Container and infrastructure controls (image scanning, network policies, least-privilege service accounts) protect the runtime.

## Performance Impact

Managed or operator-based services provide autoscaling, fast storage, and global load balancing.

## Scalability Impact

Cloud-agnostic containers and declarative infrastructure allow moving between regions and providers.

## Cost Impact

Kubernetes-ready but not required on day one; we can start on managed containers and migrate when cost-effective.

## Operational Impact

Infrastructure as code, GitOps, and automated pipelines make changes traceable and reversible.

## AI Impact

GPU or inference-specific workloads can be scheduled on dedicated nodes without rewriting the platform contract.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
