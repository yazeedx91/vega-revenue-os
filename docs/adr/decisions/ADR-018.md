# ADR-018: Workflow Engine

- **ADR ID:** ADR-018
- **Status:** Proposed
- **Group:** Messaging
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear messaging direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the workflow engine concern.

## Problem

Multiple messaging options exist for workflow engine. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Durable mission execution
- support retries and compensation
- provide observability

## Decision

Use Temporal for durable, observable mission workflows; build a custom engine only if Temporal operational cost is unacceptable.

## Alternatives

1. **Custom workflow engine**
2. **Stateless task queues without orchestration**

## Rationale

Temporal provides durability, observability, retries, and compensation patterns out of the box, accelerating mission workflow development.

## Consequences

This decision aligns the messaging domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Operational complexity
- managed service cost
- dependency on external runtime

## Mitigations

- Start with managed Temporal or SaaS
- wrap with workflow abstraction

## Security Impact

All messages carry tenant identity and are validated at ingress; audit logging is attached to the broker layer.

## Performance Impact

Asynchronous processing decouples producers from consumers, smoothing latency spikes and improving tail latency.

## Scalability Impact

Streams can be partitioned by tenant or by event type to add consumers without blocking producers.

## Cost Impact

Redis Streams reuses the existing Redis footprint; Temporal or Kafka are deferred until workload justifies it.

## Operational Impact

Durable workflows and stream offsets make failure recovery and replay predictable.

## AI Impact

Long-running AI missions and tool calls are staged on streams, allowing agents to resume and report progress.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
