# ADR-026: Memory and Context Management

- **ADR ID:** ADR-026
- **Status:** Proposed
- **Group:** AI
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear ai direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the memory and context management concern.

## Problem

Multiple ai options exist for memory and context management. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Support short-term chat
- store long-term facts
- retrieve semantically similar context

## Decision

Use Redis for short-term conversation memory, PostgreSQL for long-term structured memory, and the vector store for semantic retrieval.

## Alternatives

1. **All memory inside the LLM context window**
2. **A single memory store for every horizon**

## Rationale

Different memory horizons have different latency, durability, and cost needs. Splitting stores optimizes for each use case.

## Consequences

This decision aligns the ai domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Consistency
- stale context
- complexity of multiple stores

## Mitigations

- TTL and versioning
- relevance scoring
- synchronization between stores

## Security Impact

Provider keys, prompt data, and outputs are isolated per tenant; all high-impact actions require explicit approval.

## Performance Impact

Model routing and caching reduce both latency and cost by selecting the smallest capable model for the task.

## Scalability Impact

A multi-provider abstraction and tool registry let us add models and capabilities without core rewrites.

## Cost Impact

Usage is metered per tenant; cheaper models handle routine tasks and expensive models are reserved for complex reasoning.

## Operational Impact

Prompt versioning, model health checks, and fallback chains make AI services observable and maintainable.

## AI Impact

Structured output, confidence scoring, and citations are first-class concerns, directly improving agent reliability.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
