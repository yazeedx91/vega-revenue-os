# ADR-095: Release Strategy

- **ADR ID:** ADR-095
- **Status:** Accepted
- **Group:** Release
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear release direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the release strategy concern.

## Problem

Multiple release options exist for release strategy. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Release safely
- support tenant rollouts
- enable rollback

## Decision

Use canary and blue-green releases with tenant-aware rollout, feature flags, and automatic rollback on SLO violation.

## Alternatives

1. **Big-bang release**
2. **Blue-green only**

## Rationale

Canary with tenant-aware rollout limits blast radius and provides fast rollback while supporting controlled feature exposure.

## Consequences

This decision aligns the release domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Complex deployments
- partial failures

## Mitigations

- Feature flags
- metrics gates
- automated rollback
- runbooks

## Security Impact

Release gates include security scans, dependency checks, and signed artifacts before deployment.

## Performance Impact

Staged rollouts and canary releases let us measure latency and error rates under real load.

## Scalability Impact

Feature flags and tenant-aware rollouts allow per-tenant enablement without global blast radius.

## Cost Impact

Deployment automation reduces manual release overhead and shortens time-to-remediation.

## Operational Impact

Blue/green or canary patterns give operators a fast rollback path when metrics degrade.

## AI Impact

Model and prompt updates are versioned and released behind the same feature flags as code.

## Reversibility

Medium. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
