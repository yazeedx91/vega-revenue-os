# ADR-055: Tenant Isolation and Data Segregation

- **ADR ID:** ADR-055
- **Status:** Accepted
- **Group:** Security
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear security direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the tenant isolation and data segregation concern.

## Problem

Multiple security options exist for tenant isolation and data segregation. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- No cross-tenant queries
- strong isolation
- audit

## Decision

Enforce tenant isolation through schema, RLS, encryption, and explicit no-cross-tenant query policy.

## Alternatives

1. **Shared tables with tenant column**
2. **Full physical separation per tenant**

## Rationale

RLS and schema-based isolation provide strong protection without the cost of separate clusters per tenant.

## Consequences

This decision aligns the security domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- RLS bypass
- shared infrastructure compromise

## Mitigations

- RLS tests
- least-privilege DB roles
- encryption

## Security Impact

This decision is itself a security control; it sets the boundary for identity, authorization, encryption, and audit.

## Performance Impact

Fine-grained authorization is enforced closest to the data to avoid repeated policy checks in every layer.

## Scalability Impact

Tenant-scoped tokens and claims scale with the identity provider and are cacheable.

## Cost Impact

Reusing standards (OAuth2/OIDC, KMS, TLS) avoids custom security implementations and compliance rework.

## Operational Impact

Centralized auth, audit, and secret management reduce operational toil and incident response time.

## AI Impact

Model calls are gated by permission checks, ensuring agents cannot access cross-tenant data or privileged actions.

## Reversibility

Medium. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
