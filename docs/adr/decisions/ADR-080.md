# ADR-080: Automated Testing Strategy

- **ADR ID:** ADR-080
- **Status:** Accepted
- **Group:** Quality
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear quality direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the automated testing strategy concern.

## Problem

Multiple quality options exist for automated testing strategy. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Test code
- test contracts
- evaluate agents
- fail pipeline on regression

## Decision

Run unit, integration, contract, E2E, and AI-agent eval suites in CI with clear quality gates.

## Alternatives

1. **Manual QA only**
2. **Only unit tests**

## Rationale

A layered automated test strategy catches issues early and supports safe, frequent releases.

## Consequences

This decision aligns the quality domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Test maintenance
- flaky tests
- long CI

## Mitigations

- Test pyramid
- hermetic tests
- parallel execution

## Security Impact

Security and adversarial tests are part of the quality gate, catching injection, privilege escalation, and data leakage.

## Performance Impact

Contract tests and load tests detect integration and regression performance issues before release.

## Scalability Impact

Automated suites can be parallelized and run against ephemeral environments.

## Cost Impact

Shifting testing left reduces the cost of defects discovered in production.

## Operational Impact

Automated tests and observability-driven quality reduce the manual effort required for releases.

## AI Impact

AI-agent evaluations and red-teaming are codified, so model behavior is measured against a baseline.

## Reversibility

Medium. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
