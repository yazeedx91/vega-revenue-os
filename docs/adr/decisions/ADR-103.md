# ADR-103: Reuse Phase 10 Approval Boundary for Intelligence Gates

- **ADR ID:** ADR-103
- **Status:** Accepted
- **Group:** AI / Workflow
- **Date:** 2026-08-09
- **Decision Owners:** Architecture Board, CTO

## Context

Phase 11 needs approval gates (e.g., before high-value lead qualification, before contact enrichment) but should not invent a second approval model.

## Decision

1. Reuse the existing `Approval` aggregate and `ApprovalApplicationService` from `packages/mission-orchestrator`.
2. Add new `actionType` values as policy identifiers (`lead-qualification-review`, `contact-enrichment-review`) rather than creating a new aggregate.
3. Approval requests and decisions remain domain events under the existing aggregate.

## Alternatives

1. Create an intelligence-specific approval aggregate. Rejected: duplicate concept, harder audit trail.
2. Implement gates as workflow signals only. Rejected: decisions must be auditable domain events.

## Rationale

One approval model across all missions keeps the architecture coherent and leverages Phase 10 testing.

## Consequences

- Intelligence phases can pause at approval gates using the same mechanics as any other mission task.
- Approval configuration is controlled by policy/version, not by code changes.

## Risks

- A large number of new action types may require approval UI updates. This is intentional; action types are a lightweight extension point.

## Security Impact

No change; approvals remain tenant-scoped and event-sourced.

## Performance Impact

No additional overhead.

## Scalability Impact

None.

## Cost Impact

None.

## Operational Impact

Operations and compliance use a single approval dashboard for all missions.

## AI Impact

Human-in-the-loop review for intelligence decisions is supported without custom code.

## Reversibility

High. Action types are additive strings.
