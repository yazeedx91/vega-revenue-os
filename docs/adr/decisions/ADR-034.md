# ADR-034: Fine-Tuning versus Prompt Engineering

- **ADR ID:** ADR-034
- **Status:** Proposed
- **Group:** AI
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear ai direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the fine-tuning versus prompt engineering concern.

## Problem

Multiple ai options exist for fine-tuning versus prompt engineering. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Maximize quality
- control cost
- respect data rights
- evaluate objectively

## Decision

Start with prompt engineering, retrieval, and evaluation; fine-tune only when continuous evaluation proves consistent gains and data rights permit.

## Alternatives

1. **Fine-tune from day one**
2. **No fine-tuning ever**

## Rationale

Prompt engineering and RAG provide faster iteration and lower cost. Fine-tuning is reserved for stable, high-value patterns with sufficient data.

## Consequences

This decision aligns the ai domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Over-investment in fine-tuning
- data rights issues

## Mitigations

- Evaluation threshold
- legal review of training data
- experiment tracking

## Security Impact

Provider keys, prompt data, and outputs are isolated per tenant; all high-impact actions require explicit approval.

## Performance Impact

Model routing and caching reduce both latency and cost by selecting the smallest capable model for the task.

## Scalability Impact

A multi-provider abstraction and tool registry let us add models and capabilities without core rewrites.

## Cost Impact

Usage is metered per tenant; cheaper models handle routine tasks and expensive models are reserved for complex reasoning.

## Operational Impact

Prompt versioning, model health checks, and fallback chains make AI services observable and maintainable.

## AI Impact

Structured output, confidence scoring, and citations are first-class concerns, directly improving agent reliability.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
