# ADR-054: Multi-Tenancy Model

- **ADR ID:** ADR-054
- **Status:** Accepted
- **Group:** Security
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear security direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the multi-tenancy model concern.

## Problem

Multiple security options exist for multi-tenancy model. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Isolate tenant data
- prevent cross-tenant access
- scale efficiently

## Decision

Use tenant ID everywhere, per-tenant PostgreSQL schemas, row-level security, and resource tagging for strong isolation.

## Alternatives

1. **Shared schema with manual tenant filters**
2. **Separate database per tenant**

## Rationale

A shared PostgreSQL cluster with per-tenant schemas and RLS balances isolation, cost, and operational simplicity.

## Consequences

This decision aligns the security domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Filter bugs
- noisy neighbor
- schema management

## Mitigations

- Automated RLS tests
- query builders enforce tenant
- tenant migration tools

## Security Impact

This decision is itself a security control; it sets the boundary for identity, authorization, encryption, and audit.

## Performance Impact

Fine-grained authorization is enforced closest to the data to avoid repeated policy checks in every layer.

## Scalability Impact

Tenant-scoped tokens and claims scale with the identity provider and are cacheable.

## Cost Impact

Reusing standards (OAuth2/OIDC, KMS, TLS) avoids custom security implementations and compliance rework.

## Operational Impact

Centralized auth, audit, and secret management reduce operational toil and incident response time.

## AI Impact

Model calls are gated by permission checks, ensuring agents cannot access cross-tenant data or privileged actions.

## Reversibility

Medium. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
