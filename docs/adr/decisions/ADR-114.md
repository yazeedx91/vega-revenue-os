# ADR-114: Temporal Signal Ownership for Inbound Replies

- **ADR ID:** ADR-114
- **Status:** Proposed
- **Group:** Workflow / Conversation
- **Date:** 2026-08-12
- **Decision Owners:** Architecture Review Board, CTO

## Context

After a successful outreach send, the system must durably wait for an external reply before deciding the next step. The choice is whether this wait belongs in the existing `OutreachSequenceWorkflow` or in a separate conversation workflow.

## Decision

1. In Phase 13, inbound replies are handled as a `replyReceived` signal inside the existing `OutreachSequenceWorkflow`.
2. Temporal owns the durable timer/signal wait; the `Conversation` aggregate owns the reply state and lifecycle.
3. On signal, the workflow calls two activities:
   - `recordResponse` to update `OutreachMessageExecution` status.
   - `interpretReply` to create/update the `Conversation`, classify intent, and decide the next action.
4. A separate `ConversationWorkflow` is deferred until multi-channel, long-running conversation threads require independent scaling.

## Alternatives

1. Create a dedicated `ConversationWorkflow` now. Rejected: adds worker complexity and cross-workflow correlation before the domain model is proven.
2. Poll for replies from an external inbox inside an activity. Rejected: loses Temporal's durable signal semantics and complicates idempotency.

## Rationale

Keeping the reply wait in the sequence workflow minimizes new moving parts while clearly separating Temporal coordination from domain state.

## Consequences

- `OutreachSequenceWorkflow` becomes longer-lived; reply timeouts are configurable per workflow input.
- Future extraction to a dedicated workflow will require migrating the signal handler and correlation logic.
