# ADR-013: Vector Storage

- **ADR ID:** ADR-013
- **Status:** Proposed
- **Group:** Data
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear data direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the vector storage concern.

## Problem

Multiple data options exist for vector storage. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Store and query embeddings
- support semantic search
- keep near operational data

## Decision

Use pgvector in PostgreSQL for initial vector storage; evaluate Pinecone or Weaviate if vector workload scale demands a specialized store.

## Alternatives

1. **Pinecone from day one**
2. **Self-hosted Weaviate**

## Rationale

Co-locating vectors with operational data reduces store sprawl and data movement. It is cost-efficient at small scale and has a clear migration path.

## Consequences

This decision aligns the data domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Query performance
- index tuning
- storage growth

## Mitigations

- ivfflat and hnsw tuning
- load tests
- documented migration path to dedicated vector store

## Security Impact

PostgreSQL row-level security, encryption at rest/in transit, and tenant-isolated schemas keep per-tenant data separated.

## Performance Impact

A single operational store with proper indexing, read replicas, and connection pooling supports the common workload efficiently.

## Scalability Impact

PostgreSQL scales vertically and through read replicas; polyglot extensions are introduced only when a clear bottleneck is measured.

## Cost Impact

Using one primary engine reduces licensing and operational overhead compared to a cluster of specialized stores.

## Operational Impact

Managed PostgreSQL or operator-based deployments provide backups, point-in-time recovery, and observability.

## AI Impact

pgvector and JSONB allow documents, vectors, and relational facts to coexist, simplifying retrieval and context assembly.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
