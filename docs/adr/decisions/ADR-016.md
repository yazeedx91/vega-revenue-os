# ADR-016: Object Storage

- **ADR ID:** ADR-016
- **Status:** Proposed
- **Group:** Data
- **Date:** 2026-08-08
- **Decision Owners:** Architecture Board, CTO

## Context

The AI-Native Autonomous Revenue Employee requires clear data direction so that implementation, operations, and future evolution remain coherent. This ADR captures the relevant drivers, alternatives, and consequences for the object storage concern.

## Problem

Multiple data options exist for object storage. Without a documented decision, individual teams may choose inconsistent technologies or patterns, creating integration debt, security gaps, and operational sprawl.

## Requirements

- Store files durably
- support uploads and exports
- remain portable across clouds

## Decision

Use an S3-compatible object store such as MinIO or a cloud-native S3 equivalent for documents, exports, and media.

## Alternatives

1. **Local filesystem storage**
2. **Cloud-specific proprietary object store**

## Rationale

S3-compatible storage is portable, scalable, and integrates cleanly with document processing and export pipelines.

## Consequences

This decision aligns the data domain with the overall architecture. It enables consistency, reduces cross-cutting risk, and leaves room to revisit alternatives when validation data is available.

## Risks

- Latency for small files
- egress cost
- vendor differences in API behavior

## Mitigations

- CDN integration
- lifecycle policies
- abstraction over S3-compatible API

## Security Impact

PostgreSQL row-level security, encryption at rest/in transit, and tenant-isolated schemas keep per-tenant data separated.

## Performance Impact

A single operational store with proper indexing, read replicas, and connection pooling supports the common workload efficiently.

## Scalability Impact

PostgreSQL scales vertically and through read replicas; polyglot extensions are introduced only when a clear bottleneck is measured.

## Cost Impact

Using one primary engine reduces licensing and operational overhead compared to a cluster of specialized stores.

## Operational Impact

Managed PostgreSQL or operator-based deployments provide backups, point-in-time recovery, and observability.

## AI Impact

pgvector and JSONB allow documents, vectors, and relational facts to coexist, simplifying retrieval and context assembly.

## Reversibility

High. The decision can be revisited when validation criteria or operational constraints change; alternatives are documented and can be re-evaluated.
