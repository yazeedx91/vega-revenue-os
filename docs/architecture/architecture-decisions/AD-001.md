# AD-001: Modular Monolith with Independent Worker Pools

- **Decision ID:** AD-001
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Enterprise Architecture Board

## Decision

The initial runtime architecture will be a modular monolith for core business services, with independent worker pools for AI execution, background processing, CRM integration, analytics projection, and audit ingestion. Modules will be extracted into independent services when scaling, failure isolation, or deployment independence requires it.

## Context

The domain model defines many bounded contexts. Running each as a separate microservice from day one introduces unnecessary operational complexity and inter-service latency before scale is proven.

## Alternatives

1. Microservices from day one
2. Pure monolith with no internal boundaries
3. Modular monolith with clear extraction boundaries

## Rationale

Option 3 preserves clean domain boundaries, reduces initial operational burden, and allows incremental extraction. AI execution and analytics are separated into worker pools early because they have fundamentally different resource and scaling needs.

## Impact

- Core modules share a deployment unit but maintain independent domain boundaries.
- Cross-module communication uses events or in-process ports.
- Extraction path is documented for each module.
- Independent scaling for AI, background work, and analytics.
