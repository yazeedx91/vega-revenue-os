# AD-006: Anti-Corruption Layers for All External Providers

- **Decision ID:** AD-006
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Enterprise Architecture Board

## Decision

Every external system (Dynamics 365, Graph, Zoom, Google, email, research, LLM, identity, billing) will be accessed through an anti-corruption layer (adapter/gateway). External concepts, IDs, and schemas must not leak into the core domain.

## Context

The domain model is provider-neutral. External systems change, fail, and have provider-specific semantics.

## Alternatives

1. Use external APIs directly in core services
2. Build adapters only for CRM
3. Build adapters for all external systems

## Rationale

Provider-neutral core domain plus adapters supports future extensibility and limits blast radius of external changes.

## Impact

- Core services use domain terms only.
- External IDs stored in integration-owned value objects.
- Adapters handle mapping, retries, rate limits, and failures.
- New providers can be added without core changes.
