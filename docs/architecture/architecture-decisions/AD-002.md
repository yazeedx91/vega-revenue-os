# AD-002: Event Bus as Primary Asynchronous Backbone

- **Decision ID:** AD-002
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Enterprise Architecture Board

## Decision

An event bus will be the primary asynchronous communication backbone. It will support durable topics, point-to-point queues, delayed messages, dead-letter queues, replay, and consumer groups. Synchronous REST/HTTP remains for external client-facing APIs and some internal queries.

## Context

The system needs decoupled, durable communication between bounded contexts, workflow orchestration, and background processing.

## Alternatives

1. Direct synchronous HTTP between services
2. Pure message queues without pub/sub
3. Event bus with topics and queues

## Rationale

Event-driven architecture supports loose coupling, independent scaling, replay, and long-running workflows. A bus with both topics and queues covers domain events and commands.

## Impact

- Producers and consumers are decoupled.
- Replay and analytics projection are supported.
- Idempotency and ordering must be handled by consumers.
- Specific event bus technology will be selected in Phase 05.
