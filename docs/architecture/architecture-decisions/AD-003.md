# AD-003: Separate AI Control Plane and AI Execution Plane

- **Decision ID:** AD-003
- **Status:** Proposed
- **Date:** 2026-08-08
- **Owner:** Enterprise Architecture Board

## Decision

The AI architecture will consist of a Control Plane (policy, governance, approvals, registry) and an Execution Plane (agent runtime, LLM gateway, tool execution). The Execution Plane queries the Control Plane for authorization decisions and reports outcomes to it.

## Context

AI must be governed without compromising performance. Co-locating governance and execution could allow execution to bypass controls or create tight coupling.

## Alternatives

1. Single AI service
2. Governance embedded in execution
3. Separate control and execution planes

## Rationale

Separation of concerns ensures policy is enforced centrally and execution can scale independently. It aligns with the AI Agent Management bounded context and AI Governance bounded context.

## Impact

- Control plane provides authoritative ALLOW/REQUIRE_APPROVAL/DENY decisions.
- Execution plane never bypasses policy.
- Both planes scale independently.
- Control plane must be highly available.
